# Gentoo kernel support for the HP Googlebook (Quartz)

Drop-in files that let the Googlebook's Gentoo build and install its own
kernels with Portage. Copy the `etc/` and `usr/` trees onto the laptop
(as root, owned by root):

    tar -C gentoo --exclude=README.md -cf - etc usr | ssh root@googlebook 'tar -C / --no-same-owner -xf -'

* `etc/portage/patches/sys-kernel/gentoo-kernel/*.patch`: Portage user
  patches, applied automatically when `sys-kernel/gentoo-kernel` builds.
* `etc/kernel/config.d/50-googlebook-quartz.config`: a dist-kernel config
  fragment. It forces everything the board needs at boot to be built in
  (the rescue initramfs has no modules), with dependencies; generated by
  `tools/kfrag.py` from the drivers bound on a working boot.
* `etc/kernel/install.d/90-googlebook.install` + `usr/local/sbin/googlebook-install-kernel`:
  on `kernel-install add`, pack the kernel and its DTB into the Android boot
  images (`usr/local/lib/googlebook/mkimages.py`, with the rescue initramfs
  and files from `usr/local/share/googlebook/`) and write them to slot B,
  verified. The previous images are kept in /var/lib/googlebook/previous;
  `googlebook-install-kernel --rollback` restores them.
* `etc/googlebook/cmdline`: the kernel command line. Add `gbnet.telnet=1`
  only if you want the rescue shell on telnet, which has no password.
* `etc/NetworkManager/conf.d/googlebook.conf`: keeps the DHCP client ID to
  the MAC address and sends DNS through systemd-resolved.
* `usr/local/share/googlebook/` is not in the repository. Fill it with
  `rescue.cpio`, `vendor.cpio`, `placeholder.dtbo` and `vbmeta.img` from
  `tools/build-images.sh` (see [docs/INSTALL.md](../docs/INSTALL.md)).
* Audio:
  * `usr/share/alsa/ucm2/conf.d/x1e80100/X1E80100-Google-Quartz.conf`
    selects the CRD's UCM profile, since there is no DMI to match on.
  * `lib/firmware/updates/qcom/x1e80100/X1E80100-Google-Quartz-tplg.bin`
    is a symlink to the CRD's AudioReach topology.
  * `etc/pipewire/{client,pipewire-pulse}.conf.d/50-googlebook-upmix.conf`
    copies stereo to the second speaker pair (the speaker device has four
    channels, FL FR RL RR, one per amplifier).
* `etc/systemd/sleep.conf.d/googlebook.conf`: suspend to idle (s2idle), the
  only working sleep mode, and no hibernation. See
  [docs/SUSPEND.md](../docs/SUSPEND.md).
* `etc/systemd/system/googlebook-ec-log.service` and
  `usr/local/libexec/googlebook-ec-log`: save the Chrome EC console log at
  boot to `/var/log/ec/` (for suspend debugging, see
  [docs/SUSPEND.md](../docs/SUSPEND.md)). Enable with
  `systemctl enable googlebook-ec-log`.
* `usr/local/lib/googlebook/ath12k-board2.py`: lists and extracts
  `board-2.bin` entries, for the Wi-Fi board file
  ([docs/FIRMWARE.md](../docs/FIRMWARE.md)).

* Fingerprint reader: a Portage overlay in `var/db/repos/googlebook`, with
  `etc/portage/repos.conf/googlebook.conf` and
  `etc/portage/package.accept_keywords/googlebook-fprint`. It has
  `sys-auth/libfprint-1.94.100` with the crfpmoc driver for ChromeOS
  fingerprint MCUs ([libfprint MR !512](https://gitlab.freedesktop.org/libfprint/libfprint/-/merge_requests/512),
  pinned at 5644259) and our fixes for the Googlebook's newer MCU firmware.
  After copying it, run `ebuild /var/db/repos/googlebook/sys-auth/libfprint/libfprint-1.94.100.ebuild manifest`
  if Portage complains, then `emerge sys-auth/fprintd`, and enroll a finger
  in GNOME Settings → Users. The MCU encrypts the prints (stored in
  `/var/lib/fprint`) with a key derived from a seed that it forgets on every
  reboot; our patch keeps the seed in `/var/lib/fprint/crfpmoc-keys`
  (root-only). Losing that file means enrolling again, and so does creating
  it while the MCU already has a seed: enroll after a reboot. The kernel side needs patches 0018 to 0020 and
  `CONFIG_CROS_EC_USB=m` (in the config fragment).

Also needed on the laptop (not files here):

    /etc/portage/package.use/kernel:   sys-kernel/gentoo-kernel -initramfs -debug
                                       sys-kernel/installkernel -dracut
    /etc/portage/package.accept_keywords/kernel: =sys-kernel/gentoo-kernel-7.2.11 ~arm64
                                                 =virtual/dist-kernel-7.2.11 ~arm64

The patches are made against Linux 7.2.11 and apply cleanly to it. To apply
them to one kernel version only, rename the directory to e.g.
`gentoo-kernel-7.2.11`.

## What the patches do

* **spi: geni-qcom: Release CS left asserted …**: generic fix. Without it,
  chip select stays asserted after `cros_ec_spi`'s zero-length end-of-message
  transfer, and the Chrome EC (keyboard) rejects every command after the first.
* **phy: qcom: eusb2-repeater: Reset the repeater on init**: generic fix.
  Without it, a USB-C port that had a device attached when the bootloader
  handed over stays dead until reboot.
* **drm/panel-edp: Leave the enable GPIO alone …**: generic fix. Without
  it, Samsung OLED panels stay black after the firmware-to-Linux handover.
* **arm64: dts: qcom: …google-quartz…**: the board device tree
  (`qcom/x1e80100-google-quartz.dtb`) and its later additions:
  * USB 2.0, NVMe
  * touchpad and touchscreen
  * Wi-Fi, Bluetooth
  * display and GPU
  * the ADSP (charging, battery), USB-C, audio
  * the webcam and the fingerprint reader
* **iommu/arm-smmu-qcom, remoteproc: qcom: pas**: run the ADSP with an
  identity mapping when TrustZone can't provide a resource table.
* **platform/chrome: Add a USB transport for the ChromeOS EC**: new driver
  (`cros_ec_usb`) for MCUs that take ChromeOS EC host commands over USB, as
  the fingerprint MCU does.
* **gpio: cros-ec: Don't fail to probe on an EC without GPIOs**: generic fix;
  the fingerprint MCU reports the GPIO feature without any GPIOs.

## Regenerating

The patches come from the `quartz` branch of our kernel tree:

    git -C src/linux-7.2.11 format-patch -o <dir> e9f1f8bd7..quartz

The `bringup` branch keeps the full debugging history, including the
`DEBUG:` boot-checkpoint commit, which is not part of the patch series.
